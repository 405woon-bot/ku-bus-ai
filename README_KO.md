## 1. 실행 · 배포

```bash
# 백엔드(로컬)
cd backend && npm install
cp .env.example .env                 # SEOUL_BUS_API_KEY=발급받은_일반_인증키   (VAPID 키는 선택)
npm start                            # http://localhost:8787  (frontend/dist를 함께 제공)

# 실제 응답 확인(키는 출력하지 않음)
npm run check:live -- 정릉시장        # 정류장 이름 → 정류장 번호(arsId)
npm run check:live -- 08901          # 정류장 번호 → 국민대행 노선 · 차내 시간 · 정체 원인(화면과 같은 계산)

# 화면을 고쳤을 때만(배포용 dist · 미리보기 dist-preview 다시 만들기)
cd frontend && npm install && npm run build && npm run build:preview
```

- **Render:** 저장소에 `frontend/dist`가 들어 있어야 화면이 보입니다(`.gitignore`에 넣지 마세요). push하면 자동으로 다시 배포됩니다.
- **백그라운드 알림:** `npx web-push generate-vapid-keys` 결과를 환경 변수 `VAPID_PUBLIC_KEY` · `VAPID_PRIVATE_KEY`에, `VAPID_SUBJECT`에 `mailto:내메일`을 넣고, 외부 DB `UPSTASH_REDIS_REST_URL` · `UPSTASH_REDIS_REST_TOKEN`을 넣은 뒤 화면 설정 → **알림 켜기** → **테스트 알림 보내기**(HTTPS 필요).

### 1-1. 서버 깨우기(cron-job.org, 무료)

Render 무료 서버는 15분 동안 접속이 없으면 잠들고(다시 깨는 데 약 1분), 잠든 동안에는 1분마다 알림 시각을 확인하는 타이머도 멈춥니다. cron-job.org가 10분마다 `/api/wake`를 불러 깨워 둡니다.

| 칸 | 값 |
|---|---|
| URL | `https://<서비스 주소>.onrender.com/api/wake` (GET, 인증 없음 · 서버를 깨우기만 함) |
| 일정 | 사용자 지정(Custom): 요일 월~금 · 시 5~21 · 분 0, 10, 20, 30, 40, 50 · 시간대 **Asia/Seoul** |
| 참고 | 잠든 서버의 첫 호출은 30초 안에 답하지 못해 '실패'로 남을 수 있어요(서버는 깨어남). 다음 호출부터 성공. 월 약 380시간(평일 17시간 × 22일)으로 Render 무료 750시간 안 |

## 2-1. 강의 목록 만들기 — `tools/fetch_courses.py`

수강신청 사이트의 **공개 강좌조회(수업계획서)** 화면이 쓰는 조회 API를 그대로 불러 `backend/courses/courses.json`을 만듭니다. 표준 라이브러리만 씁니다(Python 3.9 이상).

```bash
python tools/fetch_courses.py                                  # 2026년 2학기 학부 전체(대학별 개설강좌, 요청 사이 1초)
python tools/fetch_courses.py --year 2027 --semester 1         # 다른 학기(1 · 여름 · 2 · 겨울)
python tools/fetch_courses.py --name 회로이론 --name 자료구조     # 주요 과목만(과목명 검색)
python tools/fetch_courses.py --names-file tools/my_courses.txt  # 과목명 목록 파일(한 줄에 하나)
python tools/fetch_courses.py --college 공과대학 --dept 경영학부   # 대학 · 학부(과) 단위
python tools/fetch_courses.py --raw raw.json                   # 받은 원본도 저장(문제 확인용) · --from-raw raw.json 으로 변환만
```

- **조회 방식(직접 확인):** `POST /api/subject/public/lectures/conditions/validation/ko`. `searchType "01"`(기본검색)은 과목명 · 번호 · 교수명이 필요하고, 조건 없는 '전체'는 서버가 받지 않습니다(HTTP 500). 그래서 전체는 `searchType "02"`(개설강좌)로 **대학마다** 나눠 모읍니다. 대학 · 학과 목록과 이수구분 코드표는 `GET /api/subject/public/commoncodes/all`.
- **응답 → 강의:** `lectureRoms.results[]`의 `subjectId`(번호) · `classSequence`(분반) · `subjectNm` · `professorName` · `credits` · `categoryCode`(이수구분) · `dayTime`(주야) · `schedule.lectureTimes[]`(30분 칸: 요일 · 시작 · 끝 · 강의실). 30분 칸은 같은 요일 · 같은 강의실에서 이어지면 하나로 합칩니다(월 15:00-16:30 등). 교번 같은 개인 식별 번호는 저장하지 않습니다.
- **쪽 나누기:** `offset`을 `limit`(100)씩 늘려 `totalCount`까지. 묶음 강의가 함께 와서 쪽마다 한두 건이 더 올 수 있어 강의 id로 중복을 지웁니다.
- **예의:** 학기마다 한 번만 실행하고, 수강신청 기간처럼 접속이 몰리는 때는 피하세요. 학교 정보시스템 이용 규정을 따르세요. 수강신청(장바구니 · 신청) 기능은 부르지 않습니다.
- 서버는 시작할 때 `courses.json`을 읽습니다(`COURSES_FILE`로 위치 변경 가능). 새 학기에는 스크립트를 다시 실행하고 push하세요.

## 3. 계산 (`shared/stopTrips.js` · `shared/recommend.js` — 서버와 화면이 같은 코드)

```
국민대행 노선 = 탑승 정류장 도착 정보의 노선 중, 경유 정류소에서 승차 뒤 처음 만나는
               국민대학교앞·국민대앞(정문) / 국민대후문(후문)이 있는 노선
차내 시간     = Σ (구간 거리 fullSectDist[m] ÷ 구간 속도 sectSpd[km/h]) + 중간 정류장 × 20초
도로 정체     = 승차→하차 평균 속도: 20 km/h 이상 원활 · 12 이상 보통 · 그 아래 혼잡
정체 원인     = 가장 느린 실측 구간이 15 km/h 미만이면 노선별 도로 매핑표(shared/corridors.js)의 도로 이름
후보 버스     = 노선별 실시간 도착 예정 2대(traTime, 없으면 arrmsg) + 그 뒤는 배차간격(term)으로 이은 예상 차
               (운행종료 노선은 제외, 둘째 차가 운행종료면 막차로 보고 잇지 않음)
강의실 도착   = 탑승 시각 + 차내 시간 + 하차 문 → 강의 건물 도보(표, 없으면 5분)
추천 버스     = 수업 시작 5분 전까지 강의실에 닿는 차 중 가장 늦게 타도 되는 차(없으면 가장 빨리 도착하는 차)
출발 추천     = 추천 버스 탑승 시각 − 정류장까지 걷는 시간(기본 5분)
내 걸음 반영  = '도착했어요!'로 배운 보정(정수로 반올림해 강의실 도착에 더함, shared/arrival.js)
               여유 = 수업 시작 − 누른 시각 · 늦음(여유<5): +0.5×(5−여유) 최대 +3 · 5~10분 전: 그대로
               너무 일찍(여유>10): −0.25×(여유−10) 최대 −2 · 전체 −5 ~ +15 · 한 수업에 한 번(서버 시각으로 확인)

[v2.0 출발지 환승 경로 — shared/transitPlan.js · shared/subwayArrivals.js]
첫 도보       = ODsay 도보 구간(trafficType 3)
첫 지하철     = 서울시 실시간 열차(같은 노선 · 같은 방향 · 하차역 전에 끝나는 열차 · 급행 제외) 중
               '역 입구 도착 + 승강장 2분' 뒤 첫 열차, 받은 열차 뒤로는 배차간격(ODsay)으로 이음
               실시간이 없으면 기다림 = 배차간격 절반 + 1분(정보 없으면 지하철 4 · 버스 6, 2~12분)
               barvlDt가 0(모름)이면 도착 문구로 일찍 오는 쪽으로 추정 · 5분 넘은 기록은 버림
구간 이동     = ODsay sectionTime · 환승 = ODsay 환승 도보 + 1회마다 3분 여유
마지막 버스   = 국민대행 노선이면 기존 계산 그대로(서울시 실시간 · 실시간 차내 시간 · 하차 문 → 강의 건물 도보)
출발 추천     = 수업 시작 − 여유 − 내 걸음 반영까지 닿는 가장 늦은 출발(분 단위 내림), 늦으면 '지금 출발'
알림 기록     = 직행과 따로('날짜:수업:transit') — 하루 중에 방식을 바꿔도 '앞당겨졌어요'가 잘못 울리지 않게
```

- 구간 값의 위치는 가이드 예시처럼 '앞 정류소 → 이 정류소' 구간이 도착 정류소 행에 있다고 보고, 첫 행 대신 마지막 행이 0이면 반대로 자동 판단합니다. 구간 속도가 2 km/h 이하 · 90 이상이면 15 km/h로 계산합니다.
- **알림(`decideAlarms`):** 출발 N분 전(기본 10분) 1회 · 출발 시각이 3분 이상 앞당겨지면 다시 · 빠듯/지각 위험이면 1회. 같은 날 · 같은 수업 · 같은 종류는 한 번. 화면이 열려 있으면 브라우저가, 닫혀 있으면 서버 스케줄러(1분마다, 수업 3시간 전부터)가 Web Push로 보냅니다.

## 4. 서울시 버스 API (공식 활용가이드 대조)

| 직전 값이 없거나 3분 넘음 | 예시 데이터(shared/transitModel.js 시나리오) + 이유 | 점선 안내 · 점선 카드 · [예시 데이터 · 이유] |
| 호출 한도 초과 | 15분 동안 서울시 호출 중단 → 직전 값 → 예시 데이터 | [예시 데이터 · 호출 한도 초과] |
| 키 없음 | 서울시를 부르지 않음, 정류장 검색은 이유 안내(503) | [예시 데이터 · API 키 없음] |
| 우리 서버 연결 안 됨(화면 쪽) | — | 받아 둔 값으로 계속 표시, 없으면 연결 오류 안내 |

- **호출량 어림:** 정류장 하나를 화면으로 보고 있으면 1분에 도착 정보 약 2회 + 국민대행 노선 수 × 5분에 1회. 노선 3개면 시간당 약 160회입니다. 공공데이터포털 마이페이지에서 일일 한도를 확인하고, 모자라면 `LIVE_CACHE_SEC`을 늘리세요.

- 서울특별시 버스 Open API(공공데이터포털): 정류소정보조회 · 노선정보조회 · 버스도착정보조회 · 버스위치정보조회 활용가이드. 미리보기의 샘플 응답과 예시 데이터는 실제 운행 정보가 아닙니다.
