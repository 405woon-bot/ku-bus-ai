# KU BUS AI v0.3 — 서울시 버스 실시간 API 연동

국민대학교 학생의 시간표와 이용 노선을 바탕으로, **서울시 버스 실시간 정보**로 계산한 소요시간이 평소보다 길어지면 출발 전에 알려 주는 웹 앱입니다. v0.3은 v0.1 구조(React 화면 + Express 서버 + 둘이 함께 쓰는 `shared/` 계산 모듈)를 그대로 두고, 교통 데이터 공급자를 서울시 버스 Open API로 바꿨습니다.

- **바로 보기(서버·키·네트워크 없이):** `frontend/dist-single/index.html` — 항상 **예시 데이터**(점선 배지)로 동작합니다.
- **실시간으로 돌리기:** `backend/.env`에 `SEOUL_BUS_API_KEY`를 넣고 서버를 켜면 배지가 **서울시 실시간**(청색)으로 바뀝니다. 키·네트워크·호출 한도에 문제가 생기면 자동으로 예시 데이터로 돌아가고 그 이유를 화면에 표시합니다.
- **기술:** React 18.3 · Vite 5.4 · Tailwind CSS 3.4 / Node.js 20.6+ · Express 4.21 · web-push 3.6 / (선택) Redis

> **인증키는 서버 `.env`에만 둡니다.** 이 패키지의 어떤 파일에도 키가 들어 있지 않습니다. 화면은 우리 서버(`/api/...`)만 부르고 서울시 API를 직접 부르지 않으며, `/api/health`·로그·오류 메시지에서도 키를 가립니다.

## 1. 빠른 시작

```bash
# 1) 백엔드 설정
cd backend && npm install
cp .env.example .env           # SEOUL_BUS_API_KEY=발급받은_일반_인증키   (VAPID 키는 선택)

# 2) 실제 응답 확인: 노선번호 · 내 승차 정류장 번호(arsId 5자리) · 하차 정류장 이름
npm run check:live -- 171 <승차정류장번호> 국민대학교앞

# 3) 화면 빌드 후 서버 실행
cd ../frontend && npm install && npm run build     # → dist/ (서버가 함께 제공)
cd ../backend && npm start                          # http://localhost:8787

# 4) 화면 → 알림 설정 → 노선마다 "승차 정류장 번호" 입력 (또는 "노선 정류장 불러오기"로 확인)
```

- **승차 정류장 번호(arsId)** 는 정류장 표지판의 5자리 번호입니다. 승차 정류장을 하나도 넣지 않으면 서버는 예시 데이터로 동작하고 이유를 "승차 정류장 미설정"으로 표시합니다.
- `check:live`는 키를 출력하지 않고 ① 노선 검색 ② 경유 정류소 필드 목록·구간 값 규칙 ③ 승차 정류장 도착 정보 ④ 계산된 차내 소요시간(주행 + 정차)과 가장 느린 구간 · 원인을 차례로 보여 줍니다. 인증 오류가 나면 키 파라미터 이름을 `ServiceKey` → `serviceKey` 순서로 바꿔 시도합니다.
- **서버 푸시:** `npx web-push generate-vapid-keys` 결과를 `.env`의 `VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY`에 넣고, 화면 알림 설정에서 **서버 푸시 켜기**를 누릅니다(HTTPS 또는 localhost 필요).
- **데모 빌드:** `cd frontend && npm run build:single` → `dist-single/index.html`(예시 데이터 전용, 서버 없이 열림).

## 2. 서울시 버스 API 연동 — 공식 활용가이드 기준

### 2-1. 서비스 URL · 인증키 · 형식

- 요청서의 Base URL은 `http://msg.bus.go.kr/api/rest`였지만, 함께 주신 활용가이드 4종(노선정보조회 2023-03-08, 정류소정보조회 2025-09-24, 버스도착정보조회 2025-08-14, 버스위치정보조회 2023-05-30)의 서비스 URL은 모두 **`http://ws.bus.go.kr/api/rest`** 입니다. 기본값은 가이드를 따랐고 `SEOUL_BUS_BASE_URL`로 바꿀 수 있습니다.
- 인증키 이름: 가이드 예제 URL은 `ServiceKey=`, 요청서와 일부 요청 변수 표는 `serviceKey`입니다 → `SEOUL_BUS_KEY_PARAM`. 공공데이터포털 **Encoding 키**(`%`가 들어 있는 값)는 그대로, **Decoding 키**는 URL 인코딩해서 보냅니다.
- 형식: REST GET, 기본 XML. `SEOUL_BUS_FORMAT=json`이면 `resultType=json`.

### 2-2. 쓰는 오퍼레이션

| 순서 | 오퍼레이션 (서비스) | 요청 | 쓰는 응답 필드 | 캐시 |
|---|---|---|---|---|
| ① | `busRouteInfo/getBusRouteList` (노선정보조회) | `strSrch=171` | `busRouteId` · `busRouteNm` · `routeType` | 12시간 |
| ② | `busRouteInfo/getStaionByRoute` (노선정보조회 — Staion은 API 원문 철자) | `busRouteId` | `seq` · `arsId` · `stationNm` · `fullSectDist`(m) · `sectSpd`(km/h) · `direction` · `transYn` | 30초 |
| ③ | `stationinfo/getStationByUid` (정류소정보조회, 상세기능명 getStationByUidItem) | `arsId={boardArsId}` | `busRouteId` · `arrmsg1/2` · `traTime1/2`(초) · `staOrd` · `congestion1/2` · `vehId1/2` | 30초 |

- ① 노선 이름이 정확히 같은 결과만 고릅니다(171을 검색하면 1711 등이 섞여 나옴). 노선 설정에 `busRouteId`를 직접 넣으면 검색을 건너뜁니다.
- ③은 승차 정류장의 "다음 버스 N분 후" 표시와, 왕복 노선이 같은 정류장을 두 번 지날 때 승차 순번(`staOrd`)을 고르는 데 씁니다. ③이 실패해도 ②로 계산한 소요시간은 그대로 씁니다(인증키·호출 한도 오류는 예외).

### 2-3. 응답 코드 처리

| 코드 | 가이드 의미 | 처리 |
|---|---|---|
| headerCd 0 | 정상 | 사용 |
| headerCd 3 · 4 · 7 · 8 | 정류소 없음 · 노선 없음 · 경로 검색 결과 없음 · 운행 종료 | 결과 없음(빈 목록) → 그 노선 "실시간 정보 없음" |
| headerCd 6 | 실시간 정보를 읽을 수 없음 | 일시 오류 → 직전 값 또는 폴백 |
| headerCd 1 · 2 · 5 · 그 밖 | 시스템 오류 · 잘못된 쿼리 · 잘못된 위치 | API 오류 → 직전 값 또는 폴백 |
| 게이트웨이 `returnReasonCode` 22, HTTP 429 | 호출 한도 초과 | `quota` → 15분 쿨다운 |
| 게이트웨이 20·30·31·32, `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 등 | 인증키·승인·기간 문제 | `auth` → 폴백(이유: 인증키 오류) |
| 끊긴 XML · 잘못된 JSON / 그 밖의 HTTP 오류 / 6초 무응답 | — | `parse` / `http` / `timeout` |

게이트웨이 오류 형식(`cmmMsgHeader`/`comMsgHeader`)은 활용가이드 표에 없어서 공공데이터포털 공통 형식을 기준으로 처리했습니다. 실제 오류 응답으로 확인이 필요합니다.

## 3. 소요시간(liveMin) · 정체 원인 계산 — `backend/src/transit/seoulBus.js`

```
차내 시간 = Σ (구간 거리 fullSectDist[m] ÷ 구간 속도 sectSpd[km/h])   … 승차 정류장 → 하차 정류장 사이 구간
          + 중간 정류장 수 × 20초                                    … 승차·하차 정류장은 세지 않음
liveMin   = 반올림(차내 시간)
delayMin  = max(0, liveMin − usualMin)        상태: 2분 미만 원활 · 2~4분 노랑 · 5분 이상 빨강
```

- **구간 값의 위치:** 가이드 예시에서 1번 정류소는 `fullSectDist 0 · sectSpd 0`, 2번은 `249 · 12`입니다. 즉 "앞 정류소 → 이 정류소" 구간 값이 도착 정류소 행에 있습니다. 첫 행이 0이면 이 규칙, 마지막 행이 0이면 반대 규칙으로 자동 판별합니다.
- **승차 · 하차:** 승차는 노선 설정의 `boardArsId`(5자리), 하차는 승차 뒤에 처음 나오는 `alightName`(공백 무시 비교, 비우면 노선의 하차 정류장)입니다.
- **속도 이상값:** `sectSpd`가 2 km/h 이하이거나 90 km/h 이상이면 15 km/h로 대신 계산하고, 정체 원인 판단에서는 뺍니다.
- **정체 원인:** 실측 구간 중 가장 느린 구간이 15 km/h 미만이면 ① `shared/corridors.js` 매핑표에서 노선·정류장 쌍으로 도로명(예: 171번 고려대부고→청덕초 = 정릉로) ② 노선 설정의 `corridor`·`corridorSeq` 범위 ③ 둘 다 없으면 "A→B 구간". 15 km/h 이상이면 원인 없음. **매핑표는 예시**이므로 실제 노선 정류장 순서를 보고 고쳐 주세요.
- **평소 소요시간(usualMin):** (노선 · 요일 · 15분 칸)별 지수이동평균을 하루 한 번 기록합니다. 기록이 생기기 전에는 사용자가 넣은 값을 씁니다. 같은 날 다시 읽으면 오늘 이전 값을 돌려줘서 오늘의 정체가 곧바로 '평소'가 되지 않습니다(v0.3에서 고친 버그).

`GET /api/live?routes=171` 응답 예 (테스트 고정 응답 기준, 일부 생략):

```json
{ "source": "seoul", "provider": "seoul", "cause": "정릉로", "roadDelays": { "정릉로": 6 }, "partial": false,
  "routes": [{ "id": "171", "liveMin": 18, "usualMin": 12, "delayMin": 6,
    "status": { "level": "danger", "label": "+6분 지연" }, "cause": "정릉로", "source": "seoul", "stale": false,
    "busRouteId": "900000171",
    "inVehicle": { "minutes": 17.8, "distM": 1780, "intermediateStops": 3, "board": "정릉시장", "alight": "국민대학교앞",
                   "slowest": { "from": "고려대사범대학부속고등학교", "to": "청덕초등학교입구", "kmh": 4 } },
    "arrival": { "first": { "sec": 180, "msg": "3분후[1번째 전]", "congestion": "보통" }, "ended": false } }] }
```

> **확인 필요:** 노선정보조회 가이드에 "데이터 갱신주기: 매일 새벽 5시"라고 적혀 있습니다. `getStaionByRoute`의 `sectSpd`가 분 단위로 바뀌는 실시간 속도인지는 실제 응답으로 확인하지 못했습니다. 출퇴근 시간에 값이 변하지 않으면, 버스위치정보(`getBusPosByRtid`)의 정류소 통과 시각으로 구간 속도를 보정하는 것을 다음 단계로 권장합니다.

## 4. 캐시 · 폴백 규칙 — `backend/src/transit/index.js`

| 상황 | 서버 동작 | 화면 배지 |
|---|---|---|
| 정상 | 정류장·도착 결과 30초 캐시(노선ID 12시간), 같은 요청은 동시에 1번만, 최근 15분 안에 요청된 노선은 30초마다 미리 갱신 | 청색 **서울시 실시간** |
| 일시 오류(네트워크 · 시간 초과 · 해석 · 서버 오류) | 직전 정상값이 3분 이내면 그 값(`stale: true`, `ageSec`) | 청색 + "잠시 전 값", 노선 목록에 "N초 전 값" |
| 정상값이 없거나 3분 넘음, 모든 노선 실패 | `shared/transitModel.js` 예시 데이터로 폴백, `reason` 기록 | 점선 **예시 데이터 · {이유}** |
| 일부 노선만 실패 | 그 노선만 `liveMin: null` + 오류. 예시 값을 섞지 않음 | 그 노선 "실시간 정보 없음" |
| 호출 한도 초과 | 15분 동안 서울시 호출 중단 → 직전 값(3분) → 예시 데이터 | 예시 데이터 · 호출 한도 초과 |
| 인증키 없음 / 인증키 오류 | 호출하지 않음 / 폴백 | 예시 데이터 · API 키 없음 / 인증키 오류 |
| 승차 정류장 미설정 | 그 노선은 설정 오류, 모두 미설정이면 폴백 | 예시 데이터 · 승차 정류장 미설정 |
| 우리 서버에 연결 안 됨(화면 쪽) | — | 직전 서울시 값 유지, 없으면 화면에서 예시 데이터 · 우리 서버 연결 안 됨 |

- 폴백 이유가 여러 개면 사용자가 고칠 수 있는 것부터 보여 줍니다: API 키 없음 → 인증키 오류 → 호출 한도 → 승차 정류장 미설정 → 해석 오류 → 시간 초과 → 네트워크 → 서버 오류 → 일시 중단 → API 오류.
- **호출량 어림:** 활성 시간 동안 1분에 약 (노선 수 + 서로 다른 승차 정류장 수) × 2회. 노선 3개 · 승차 정류장 1곳이면 분당 8회, 수업 전 3시간이면 약 1,440회입니다(같은 노선을 쓰는 사용자끼리는 캐시를 함께 씀). 공공데이터포털 마이페이지에서 개발계정 일일 한도를 확인하고, 모자라면 `LIVE_CACHE_SEC=60`처럼 늘리세요.

## 6. 알림 스케줄러 · Web Push — `backend/src/scheduler.js`

- 1분마다 모든 사용자를 화면과 **같은 함수**(`shared/departure.js`의 `buildPlan` · `decideAlarms`)로 계산해 Web Push를 보냅니다. 수업 시작 180분 전부터 시작 전까지만 계산하므로 그 밖의 시간에는 서울시 API를 부르지 않습니다.
- 같은 날 · 같은 수업 · 같은 종류의 알림은 한 번만 보냅니다. 예시 데이터로 계산한 알림은 따로 기록해서, 뒤에 실시간 데이터가 들어오면 실시간 기준 알림이 다시 나갈 수 있습니다.
- 예시 데이터로 계산한 푸시는 본문 끝에 " (예시 교통 데이터 기준 · 실시간 아님)"을 붙이거나(`PUSH_WHEN_MOCK=label`) 보내지 않습니다(`skip`). 화면 알림도 본문에 같은 표시를 붙이고, 실시간 알림이 오면 예시 알림 팝업을 치우며, 최근 알림 기록에는 "(예시 데이터 기준)"을 남깁니다.

## 7. 화면 (`frontend/`)

- **데이터 출처 배지** (`components/ui.jsx`의 `SourceTag`): 실시간이면 청색 **서울시 실시간**, 예시 데이터면 점선 **예시 데이터 · {이유}**. 헤더(넓은 화면), ① 지연 알림 카드, ③ 노선별 비교, ⑦ 알림 설정의 서버 패널에 나옵니다. 정체 지도는 예시일 때 점선 배지, 실시간일 때 "정체 구간: 서울시 구간 속도로 추정 · 버스 위치 표시는 예시" 안내를 붙이고, 버스 위치 토글은 항상 "버스 위치(예시)"로 적습니다(지도 위 버스 점은 실시간 GPS가 아님).
- **지연 알림 카드** (`AlertRouteCard`): 주 노선의 출처로 배지를 정하고, 승차 정류장 도착 정보(예: "다음 버스 3분후[1번째 전]")를 보여 줍니다. 주 노선 실시간 정보가 없으면 그 사실과 대신 쓴 노선을 알립니다.
- **알림 설정** (`AlarmSettings`): 노선마다 **승차 정류장 번호**(5자리)와 **하차 정류장 이름**(목록에서 고르기) 입력, **노선 정류장 불러오기**(서버가 getStaionByRoute로 가져온 목록), 노선별 상태 줄(예: "서울시 실시간: 정릉시장 → 국민대학교앞 차내 17.8분(중간 정류장 3곳 × 20초 포함)").
- **서버 패널:** 실시간 데이터 출처 배지, "서버와 동기화됨(synced)" / "서버 동기화 오류(error)", **서버 푸시 켜기** → 서비스 워커 등록 → VAPID 구독 → 서버 저장 → "서버 푸시 켜짐(synced)" 또는 "서버 푸시 오류(error)"와 원인·**다시 시도**.
- **데이터 흐름** (`hooks/useLiveRoutes.js`): api 빌드는 `/api/live`를 30초마다 부르고, 정류장 설정을 바꾸면 저장(0.6초) 뒤 곧바로 다시 부릅니다. 단일 HTML 데모 빌드는 네트워크 없이 예시 데이터만 씁니다.

화면 구성(v0.1과 같음): ① 지연 알림 + 대체 노선 ② 첫 수업 · 권장 출발 계산식 ③ 노선별 실시간 비교 ④ 에브리타임식 시간표 ⑤ 정체 지도 ↔ 3D 트윈 ⑥ 건물별 도보시간 ⑦ 알림 설정. 모바일은 한 열로 쌓입니다. 스크린샷: `test/screenshots/`.

## 8. 권장 출발 시각 계산 — `shared/departure.js` (백엔드 · 화면 공용)

```
권장 출발 시각 = 수업 시작 − 건물 도보시간(노선의 하차 문 기준) − 여유 5분 − 실시간 버스 소요(liveMin)
알림 시각      = 권장 출발 − N분(기본 10분)
```

- 백엔드 `planner.js`와 화면 `App.jsx`가 같은 `buildPlan`과 같은 원인 선택 함수 `causeFor`(주 노선의 원인 → 전체 원인)를 씁니다. 테스트에서 `/api/plan` 결과와, `/api/live` 응답으로 화면 경로를 그대로 재현한 결과가 권장 출발 · 알림 시각 · 문구 · 노선별 출발 시각까지 같은지 확인합니다.
- 예(테스트 고정 응답): 월 09:00 미래관, 171번 liveMin 18분, 정문→미래관 4분 → 09:00 − 4 − 5 − 18 = **08:33**, 문구 "현재 정릉로 정체로 171번 6분 지연! 8:33까지 출발을 권장합니다. (대체 추천: 후문 방향 1112번 탑승 시 정시 출발 가능)".
- 대체 노선 · 알림 판정(조기 지연 → 출발 N분 전 → 악화 → 수업 시작 후 중단)은 v0.1과 같습니다.

## 11. 그대로인 기능 (v0.1)

- **시간표 입력:** 빈 칸 클릭 · 끌기로 추가, 수업 추가/수정/삭제 대화상자(요일 여러 개 · 시각 또는 교시 · 건물/강의실 · 색), 텍스트 붙여 넣기(`자료구조 월수 09:00-10:15 미래관 301` 등 5가지 형식), 에브리타임 캡처 이미지 인식(+OCR 베타, 브라우저 안에서만 처리).

- **정체 지도 · 3D 트윈:** OSM 도로 위 정체 구간 색칠, 하차 정류장 → 출입문 → 건물 도보 경로, `KU_Bus_3D_V4.html` 새 탭 연결(3D 버스는 가상 운행).
