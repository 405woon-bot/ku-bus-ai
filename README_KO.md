# KU BUS AI v0.4 — 탑승 정류장 하나로 끝나는 등교 출발 알림 (서울시 실시간)

앱을 열면 계산 과정 없이 **"몇 시에 나가서 몇 번 버스를 타야 늦지 않는지"** 만 보여 줍니다.
v0.4는 v0.2의 화면 디자인(홈 3요소 · 탭 · 탑승 정류장 하나)에 v0.3의 서울시 실시간 연동(검증한 응답 해석 · 캐시 · 예시 데이터 전환 · 출처 배지 · 서버 푸시)을 합쳤습니다.

- **배포(Render):** Root Directory `backend` · Build `npm install` · Start `npm start` · 환경 변수 `SEOUL_BUS_API_KEY`. 화면은 빌드된 `frontend/dist`가 저장소에 들어 있어 Render에서 따로 빌드하지 않습니다.
- **미리보기(서버·키·네트워크 없이):** `frontend/dist-preview/index.html` — 서울시 API 형식의 샘플 응답을 재생합니다(실시간 아님). 위쪽 "배지 보기"로 실시간 연결 / 잠시 끊김 / 실시간 실패 화면을 바꿔 볼 수 있습니다.
- **기술:** React 18.3 · Vite 5.4 · Tailwind CSS 3.4 / Node.js 20.6+ · Express 4.21 · web-push 3.6 / (선택) Redis

> **인증키는 서버 환경 변수(`backend/.env` 또는 Render Environment)에만 둡니다.** 이 패키지의 어떤 파일에도 키가 없고, 화면은 우리 서버(`/api/...`)만 부릅니다.

## 1. 실행 · 배포

```bash
# 백엔드(로컬)
cd backend && npm install
cp .env.example .env                 # SEOUL_BUS_API_KEY=발급받은_일반_인증키   (VAPID 키는 선택)
npm start                            # http://localhost:8787  (frontend/dist를 함께 제공)

# 실제 응답 확인(키는 출력하지 않음)
npm run check:live -- 정릉시장        # 정류장 이름 → 정류장 번호(arsId)
npm run check:live -- 08901          # 정류장 번호 → 국민대행 노선 · 차내 시간 · 정체 원인(화면과 같은 계산)

# 화면을 고쳤을 때만(배포용 dist · 미리보기 dist-preview 다시 만들기)
cd frontend && npm install && npm run build && npm run build:preview
```

- **Render:** 저장소에 `frontend/dist`가 들어 있어야 화면이 보입니다(`.gitignore`에 넣지 마세요). push하면 자동으로 다시 배포됩니다.
- **서버 푸시:** `npx web-push generate-vapid-keys` 결과를 환경 변수 `VAPID_PUBLIC_KEY` · `VAPID_PRIVATE_KEY`에 넣고, 화면 설정 → 서버 푸시 켜기(HTTPS 필요).

## 3. 계산 (`shared/stopTrips.js` · `shared/recommend.js` — 서버와 화면이 같은 코드)

```
국민대행 노선 = 탑승 정류장 도착 정보의 노선 중, 경유 정류소에서 승차 뒤 처음 만나는
               국민대학교앞·국민대앞(정문) / 국민대후문(후문)이 있는 노선
차내 시간     = Σ (구간 거리 fullSectDist[m] ÷ 구간 속도 sectSpd[km/h]) + 중간 정류장 × 20초
도로 정체     = 승차→하차 평균 속도: 20 km/h 이상 원활 · 12 이상 보통 · 그 아래 혼잡
정체 원인     = 가장 느린 실측 구간이 15 km/h 미만이면 노선별 도로 매핑표(shared/corridors.js)의 도로 이름
후보 버스     = 노선별 실시간 도착 예정 2대(traTime, 없으면 arrmsg) + 그 뒤는 배차간격(term)으로 이은 예상 차
               (운행종료 노선은 제외, 둘째 차가 운행종료면 막차로 보고 잇지 않음)
강의실 도착   = 탑승 시각 + 차내 시간 + 하차 문 → 강의 건물 도보(표, 없으면 5분)
추천 버스     = 수업 시작 5분 전까지 강의실에 닿는 차 중 가장 늦게 타도 되는 차(없으면 가장 빨리 도착하는 차)
출발 추천     = 추천 버스 탑승 시각 − 정류장까지 걷는 시간(기본 5분)
```

- 구간 값의 위치는 가이드 예시처럼 '앞 정류소 → 이 정류소' 구간이 도착 정류소 행에 있다고 보고, 첫 행 대신 마지막 행이 0이면 반대로 자동 판단합니다. 구간 속도가 2 km/h 이하 · 90 이상이면 15 km/h로 계산합니다.
- **알림(`decideAlarms`):** 출발 N분 전(기본 10분) 1회 · 출발 시각이 3분 이상 앞당겨지면 다시 · 빠듯/지각 위험이면 1회. 같은 날 · 같은 수업 · 같은 종류는 한 번. 화면이 열려 있으면 브라우저가, 닫혀 있으면 서버 스케줄러(1분마다, 수업 3시간 전부터)가 Web Push로 보냅니다.

## 4. 서울시 버스 API (공식 활용가이드 대조)

| 쓰임 | 오퍼레이션 | 요청 | 쓰는 응답 필드 | 캐시 |
|---|---|---|---|---|
| 정류장 이름 검색 | `stationinfo/getStationByName` | `stSrch` | `stId` · `stNm` · `arsId` · `tmX` · `tmY`(WGS84) | 6시간 |
| 내 주변 정류장 | `stationinfo/getStationByPos` | `tmX`(경도) · `tmY`(위도) · `radius`(400 m) | `stationId` · `stationNm` · `arsId` · `gpsX` · `gpsY` · `dist` | 6시간 |
| 정류장 도착 정보 | `stationinfo/getStationByUid` (상세기능명 getStationByUidItem) | `arsId` | `busRouteId` · `rtNm` · `routeType` · `staOrd` · `term` · `traTime1·2`(초) · `arrmsg1·2` · `congestion1·2` | 30초 |
| 노선 경유 정류소 | `busRouteInfo/getStaionByRoute` | `busRouteId` | `seq` · `arsId` · `stationNm` · `fullSectDist`(m) · `sectSpd`(km/h) | 5분 |

- 서비스 URL은 가이드의 `http://ws.bus.go.kr/api/rest`(요청서의 `msg.bus.go.kr`가 아님). 기본 XML, `resultType=json`도 해석.
- 응답 코드: headerCd 0 정상 · 3/4/7/8 결과 없음(빈 목록) · 6 일시 오류 · 1/2/5 오류. 공공데이터포털 게이트웨이의 한도 초과(22)·인증 오류(20/30/31/32 등)는 따로 구분합니다(가이드 표에 없는 형식이라 실제 오류 응답으로 확인 필요).
- 이 정류장에서 국민대로 가지 않는 노선은 12시간 동안 경유 정류소를 다시 부르지 않습니다.

## 5. 캐시 · 예시 데이터 전환

| 상황 | 서버 동작 | 화면 |
|---|---|---|
| 정상 | 위 캐시, 같은 요청은 동시에 한 번만 | [● 서울시 실시간] |
| 잠깐 실패(네트워크 · 시간 초과 · 해석 · 서버 오류) | 3분 이내 직전 값(도착 예정은 흐른 시간만큼 줄임) | [서울시 실시간 · 잠시 전 값] + "N초 전 정보예요" |
| 직전 값이 없거나 3분 넘음 | 예시 데이터(shared/transitModel.js 시나리오) + 이유 | 점선 안내 · 점선 카드 · [예시 데이터 · 이유] |
| 호출 한도 초과 | 15분 동안 서울시 호출 중단 → 직전 값 → 예시 데이터 | [예시 데이터 · 호출 한도 초과] |
| 키 없음 | 서울시를 부르지 않음, 정류장 검색은 이유 안내(503) | [예시 데이터 · API 키 없음] |
| 우리 서버 연결 안 됨(화면 쪽) | — | 받아 둔 값으로 계속 표시, 없으면 연결 오류 안내 |

- **호출량 어림:** 정류장 하나를 화면으로 보고 있으면 1분에 도착 정보 약 2회 + 국민대행 노선 수 × 5분에 1회. 노선 3개면 시간당 약 160회입니다. 공공데이터포털 마이페이지에서 일일 한도를 확인하고, 모자라면 `LIVE_CACHE_SEC`을 늘리세요.

## 6. 백엔드 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/stops?q=` | 정류장 이름 검색(2글자 이상). 키 없음 · 한도 503 |
| GET | `/api/stops/near?lat=&lon=` | 내 주변 정류장(반경 400 m, 가까운 순) |

| GET · PATCH | `/api/me` | 시간표 · 탑승 정류장 · 설정(`X-User-Id` 헤더, 데모 수준 식별). 정류장 번호는 5자리 |
| PUT | `/api/me/timetable` · POST `/api/me/timetable/import-text` | 시간표 저장 · 텍스트 해석 |
| GET | `/api/plan` | 서버 쪽 추천(화면과 같은 계산) + 지금 보낼 알림 |
| GET | `/api/health` | 실시간 공급자(seoul/mock) · 이유 · 캐시 · 호출 수 · 서버 푸시 · 스케줄러 상태 |
| GET/POST | `/api/push/key` · `/api/push/subscribe` | Web Push(VAPID) |
| GET | `/api/live?routes=` · `/api/routes/:no/stations` · PATCH `/api/me/settings` | v0.3 노선별 API(호환용, 화면은 쓰지 않음) |

**하지 못한 것:** 이 작업 환경에서는 서울시 서버에 접속할 수 없어 실제 응답으로는 시험하지 못했습니다(필드는 활용가이드로 대조, 테스트는 가이드 형식의 고정 응답). 배포 뒤 `npm run check:live -- <정류장번호>`로 확인해 주세요. 특히 ① 국민대 정류장 이름(국민대학교앞 · 국민대앞 · 국민대후문)이 실제 응답과 같은지 ② `sectSpd`가 출퇴근 시간에 바뀌는지(노선정보 갱신주기가 '매일 새벽 5시'로 적혀 있음) ③ 실제 Web Push 수신.
