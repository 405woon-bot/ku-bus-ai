## 0-5. v2.2.1 → v2.2.2 — 사용자 ID 강화 · 공용 'demo' 분리 (화면 변경 없음)

로그인이 없는 이 앱에서 사용자 ID(`X-User-Id`)는 서버 기록을 찾는 유일한 열쇠입니다. 데이터 정책 점검(2026-11-23)에서 찾은 두 문제를 가장 보수적으로 고쳤습니다.

- **새 사용자는 긴 무작위 ID:** `crypto.getRandomValues` 128비트 → `u` + 32자(0-9 a-f). 예전에는 `Math.random()` 기반 `u` + 8자였습니다.
- **기존 사용자는 그대로(하위 호환):** 이 기기에 이미 있는 ID는 모양을 따지지 않고 그대로 씁니다. 예전 8자 ID의 시간표 · 알림 구독 · 도착 기록은 바뀌지 않고, ID를 옮기는 작업(마이그레이션)도 하지 않습니다.
- **공용 'demo' 분리:** 예전 화면은 저장 공간(localStorage)이 막힌 기기(예: Safari '모든 쿠키 차단', 쓰기가 안 되는 개인 정보 보호 모드)에서 모두 같은 `demo`를 보내 서로의 시간표 · 출발지가 섞일 수 있었습니다. 이제는 ① 쿠키가 되면 쿠키에 이 기기만의 ID를 남겨 새로고침해도 이어지고 ② 쿠키도 막혔으면 그 페이지에서만 쓰는 임시 ID를 씁니다(새로 열면 새 임시 ID — 남길 곳이 없어 기록이 이어지지 않는 대신 다른 사람과 섞이지 않음). 저장 공간에 `demo`가 남아 있거나 이어받기로 `demo`를 받으면 쓰지 않고 새 ID로 시작합니다.
- **서버 동작은 그대로:** 헤더 값이 곧 사용자이고 헤더가 없으면 지금처럼 `demo`입니다(cron-job.org · 서비스 워커 요청 등). 바뀐 점은 `/api/health`의 **`identity`** 하나 — ID 종류별 개수(`users.long` 새 ID · `short` 예전 8자 · `other` 그 밖, 이번 실행에서 요청을 보낸 ID 포함), `demoHeader`(화면이 `demo`를 보낸 요청 수 · 마지막 시각), `demoUser`(공용 `demo` 기록이 있으면 수업 · 구독 개수와 저장 여부만). ID 값과 기록 내용은 싣지 않습니다.
- **코드:** `shared/userId.js`(새 ID 만들기 · 종류 · 이 페이지의 ID 정하기 — 화면과 서버가 같은 코드) · `frontend/src/lib/api.js`(이 모듈 사용) · `frontend/src/lib/identity.js`(`demo` 이어받기 거절) · `backend/src/server.js`(`identity` 점검 값).
- **배포 뒤 확인(확인 필요):** ① `/api/health`의 `identity.demoHeader`가 0으로 머무는지(예전 화면이 열려 있던 기기는 새로고침 전까지 셀 수 있음) ② 시크릿 창 등 새 브라우저로 앱을 열면 `identity.users.long`이 1 늘어나는지 ③ `identity.demoUser`가 `null`이 아니면 예전에 공용으로 쓰던 기록이 남아 있다는 뜻 — 지우는 것은 사용자 승인 뒤 2단계(90일 자동 삭제 · 삭제 기능)와 함께 정합니다. 실제 저장 공간이 막힌 휴대폰(Safari 쿠키 차단 · 카카오톡 등 인앱 브라우저)에서는 아직 확인하지 못했습니다(이 작업 환경에서는 헤드리스 Chromium에서 저장 공간 · 쿠키를 막아 시험).

## 2-1. 강의 목록 만들기 — `tools/fetch_courses.py`

수강신청 사이트의 **공개 강좌조회(수업계획서)** 화면이 쓰는 조회 API를 그대로 불러 `backend/courses/courses.json`을 만듭니다. 표준 라이브러리만 씁니다(Python 3.9 이상).

```bash
python tools/fetch_courses.py                                  # 2026년 2학기 학부 전체(대학별 개설강좌, 요청 사이 1초)
python tools/fetch_courses.py --year 2027 --semester 1         # 다른 학기(1 · 여름 · 2 · 겨울)
python tools/fetch_courses.py --name 회로이론 --name 자료구조     # 주요 과목만(과목명 검색)
python tools/fetch_courses.py --names-file tools/my_courses.txt  # 과목명 목록 파일(한 줄에 하나)
python tools/fetch_courses.py --college 공과대학 --dept 경영학부   # 대학 · 학부(과) 단위
python tools/fetch_courses.py --raw raw.json                   # 받은 원본도 저장(문제 확인용) · --from-raw raw.json 으로 변환만
```

- **조회 방식(직접 확인):** `POST /api/subject/public/lectures/conditions/validation/ko`. `searchType "01"`(기본검색)은 과목명 · 번호 · 교수명이 필요하고, 조건 없는 '전체'는 서버가 받지 않습니다(HTTP 500). 그래서 전체는 `searchType "02"`(개설강좌)로 **대학마다** 나눠 모읍니다. 대학 · 학과 목록과 이수구분 코드표는 `GET /api/subject/public/commoncodes/all`.
- **응답 → 강의:** `lectureRoms.results[]`의 `subjectId`(번호) · `classSequence`(분반) · `subjectNm` · `professorName` · `credits` · `categoryCode`(이수구분) · `dayTime`(주야) · `schedule.lectureTimes[]`(30분 칸: 요일 · 시작 · 끝 · 강의실). 30분 칸은 같은 요일 · 같은 강의실에서 이어지면 하나로 합칩니다(월 15:00-16:30 등). 교번 같은 개인 식별 번호는 저장하지 않습니다.
- **쪽 나누기:** `offset`을 `limit`(100)씩 늘려 `totalCount`까지. 묶음 강의가 함께 와서 쪽마다 한두 건이 더 올 수 있어 강의 id로 중복을 지웁니다.
- **예의:** 학기마다 한 번만 실행하고, 수강신청 기간처럼 접속이 몰리는 때는 피하세요. 학교 정보시스템 이용 규정을 따르세요. 수강신청(장바구니 · 신청) 기능은 부르지 않습니다.
- 서버는 시작할 때 `courses.json`을 읽습니다(`COURSES_FILE`로 위치 변경 가능). 새 학기에는 스크립트를 다시 실행하고 push하세요.

```
구간 이동     = ODsay sectionTime · 환승 = ODsay 환승 도보 + 1회마다 3분 여유
마지막 버스   = 국민대행 노선이면 기존 계산 그대로(서울시 실시간 · 실시간 차내 시간 · 하차 문 → 강의 건물 도보)
출발 추천     = 수업 시작 − 여유 − 내 걸음 반영까지 닿는 가장 늦은 출발(분 단위 내림), 늦으면 '지금 출발'
알림 기록     = 직행과 따로('날짜:수업:transit') — 하루 중에 방식을 바꿔도 '앞당겨졌어요'가 잘못 울리지 않게
```

- 구간 값의 위치는 가이드 예시처럼 '앞 정류소 → 이 정류소' 구간이 도착 정류소 행에 있다고 보고, 첫 행 대신 마지막 행이 0이면 반대로 자동 판단합니다. 구간 속도가 2 km/h 이하 · 90 이상이면 15 km/h로 계산합니다.
- **알림(`decideAlarms`):** 출발 N분 전(기본 10분) 1회 · 출발 시각이 3분 이상 앞당겨지면 다시 · 빠듯/지각 위험이면 1회. 같은 날 · 같은 수업 · 같은 종류는 한 번. 화면이 열려 있으면 브라우저가, 닫혀 있으면 서버 스케줄러(1분마다, 수업 3시간 전부터)가 Web Push로 보냅니다.

| 쓰임 | 오퍼레이션 | 요청 | 쓰는 응답 필드 | 캐시 |

## 5. 캐시 · 예시 데이터 전환

| 상황 | 서버 동작 | 화면 |
|---|---|---|
| 정상 | 위 캐시, 같은 요청은 동시에 한 번만 | [● 서울시 실시간] |
| 잠깐 실패(네트워크 · 시간 초과 · 해석 · 서버 오류) | 3분 이내 직전 값(도착 예정은 흐른 시간만큼 줄임) | [서울시 실시간 · 잠시 전 값] + "N초 전 정보예요" |

- **호출량 어림:** 정류장 하나를 화면으로 보고 있으면 1분에 도착 정보 약 2회 + 국민대행 노선 수 × 5분에 1회. 노선 3개면 시간당 약 160회입니다. 공공데이터포털 마이페이지에서 일일 한도를 확인하고, 모자라면 `LIVE_CACHE_SEC`을 늘리세요.
